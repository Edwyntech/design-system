# Architecture & Standards Techniques

Le Design System Edwyn repose sur une architecture moderne sans compromis, axée sur la pérennité, la rapidité d'exécution et l'indépendance vis-à-vis des frameworks.

### 1. Standard W3C Custom Elements v1

Chaque composant hérite de `LitElement` et s'enregistre via le registre global `customElements.define('edwyn-*')`. Cela garantit :

- Zéro dépendance vers un framework tiers propriétaire.
- Portabilité à 100% à travers le temps et les évolutions techniques de l'écosystème web.

### 2. Lit 3.3 : Un Moteur Réactif Ultra-Léger

Lit n'utilise pas de DOM Virtuel (vDOM) coûteux en mémoire. Il analyse les gabarits HTML tagged template literals (`html`...``) au premier rendu et met à jour chirurgicalement uniquement les nœuds DOM dynamiques modifiés.

- Overhead runtime : **~5 kB** gzippé seulement.
- Vitesse de mise à jour DOM égale ou supérieure aux frameworks JS les plus récents.

### 3. Shadow DOM & Adopted StyleSheets

Tous les styles des composants sont isolés à l'intérieur du Shadow Root :

- **Imperméabilité CSS** : Aucun style externe (ex: un reset CSS global agressif ou des classes Tailwind globales) ne peut corrompre le rendu interne d'un composant Edwyn.
- **Points d'extension standard** : La personnalisation s'effectue via les variables CSS (`var(--edwyn-*)`), les pseudo-éléments d'ombrage standard (`::part(name)`), et les slots de projection de contenu (`<slot name="prefix">`).

### 4. Custom Elements Manifest (CEM) & Open Tooling

Le projet génère automatiquement un fichier `custom-elements.json` conforme à la spécification W3C Open Web Components :

- **Documentation automatique** : Storybook lit ce manifeste directement sans aucune configuration manuelle redondante.
- **IntelliSense IDE** : Fichier `web-types.json` généré pour l'autocomplétion automatique dans WebStorm et VS Code.
- **Garantie de typage** : Tous les attributs, propriétés, slots et événements sont typés et documentés à la source dans le code TypeScript.

## 📐 Anatomie d'un Composant Lit Edwyn

Chaque composant dans `src/components/` suit un agencement rigoureux et testable :

```
src/components/button/
├── edwyn-button.ts          # Définition de classe LitElement & Shadow DOM
├── edwyn-button.stories.ts  # Stories Storybook CSF 3 & tests d'interaction
└── index.ts                 # Export public du composant
```

### Exemple de Déclaration Typée

```typescript
import { LitElement, html, css } from 'lit';
import { customElement, property } from 'lit/decorators.js';

/**
 * Bouton d'action standard d'Edwyn.
 *
 * @summary Bouton interactif avec variantes stylistiques
 * @tag edwyn-button
 *
 * @slot - Libellé ou contenu principal du bouton
 * @slot prefix - Icône ou élément visuel positionné avant le texte
 * @slot suffix - Icône positionnée après le texte
 *
 * @csspart button - Élément HTML natif <button> interne
 * @cssprop --edwyn-color-primary - Couleur d'accentuation principale
 *
 * @fires click - Émis lors du clic utilisateur
 */
@customElement('edwyn-button')
export class EdwynButton extends LitElement {
  @property({ type: String })
  variant: 'primary' | 'secondary' | 'outline' | 'ghost' | 'simulator' = 'primary';

  override render() {
    return html`
      <button part="button" class="btn btn-${this.variant}">
        <slot name="prefix"></slot>
        <slot></slot>
        <slot name="suffix"></slot>
      </button>
    `;
  }
}
```

## 🛡️ Stratégie de Qualité & Tests

Le Design System applique les principes du **Software Craftsmanship** :

- **Tests unitaires rapides** : Vitest avec environnement Happy DOM pour tester les propriétés, les slots, les classes CSS et les événements émis.
- **Tests Storybook réels** : Exécution automatisée en navigateur Chromium headless via Playwright pour tester les play functions et les régressions visuelles / d'accessibilité.
- **Audit Accessibilité a11y** : Validation continue WCAG 2.1 AA intégrée à la chaîne d'intégration.
